# MCTS 实验台账

## 每轮协议

1. 保存上一版源码快照、Git 基准、改动 patch、假设和唯一实验变量，再开始改动。
2. 回归测试必须通过；测试通过不代表棋力提高。
3. 同种子成对交换座次，串行运行。分别比较同墙钟预算和同模拟次数，记录双方实际模拟数、耗时、胜负、和棋、回合上限及非法行动。
4. 有希望的候选再用未参与调整的独立种子复核。小样本只能标记“初步信号”，不能宣布稳定提升；不同时间预算的胜率不能用于证明代码改进。
5. 结论明确标记：保留（功能修复）、保留（棋力证据）、效果不确定或撤回。没有证据不默认叠加到下一轮；撤回候选也保存 patch 和结果。
6. 每轮验证完成后 commit 源码、测试、记录和原始数据；不提交未经验证的中间态。基准脚本/记录工具的改动至少跑 CLI 验证，不将其称为棋力改进。

## 环境与来源

- 初始 Git 基准：`48a5fb847dd05e53168552dbbdb4a7b2929be8f2`。
- Bun `1.3.10`，Linux x86_64；运行环境/源码校验值见 `environment.txt`、`source-sha256.txt`。
- 基准脚本：`scripts/mcts-benchmark.ts`，不调用 LLM，不生成对局会话；双方非法/失败行动会使整轮无效。
- 每对局使用同一个开局 seed、固定先手座位 0，候选分别坐 0/1；下一对 seed 加 7919。双方 agent seed 均为 7。
- `baseline-original.ts` 冻结最初 MCTS，只有移植 import 路径及增加固定 `playouts` 循环控制，未改策略。`baseline-004.ts` 冻结特权修复后版本，只有 import 路径移植。
- 001–006 为本轮建立台账前的历史数据归档。原始日志中的 `/tmp/splender-mcts-before.ts` 对应 `baseline-original.ts`；001–003 的全部中间源码未保存，不能宣称能完整复现当时实现。
- 墙钟模式受机器负载影响，同种子不能保证相同行动；固定模拟次数用于确定性复现。吞吐必须在相同局面分布下比较，不将中局单步速度与整局均值混用。

## 007：被撤回的需求权重候选

假设：提高缩短购买缺口的 token 价值，可以改善固定偏爱珍珠的行动排序和贪心 rollout。

实现：每个局面预计算每色前 3 枚 token 的边际权重；在原始 token 价值上增加 `12 / 剩余购买缺口`，各可见卡取最大值。扣除已有 token、折扣和黄金，跳过无叠放资格的百搭卡。仅改变拿取排序/rollout 分数，未改 UCT、购买分数或搜索预算。

行为测试先失败（旧版拿珍珠），候选通过（拿解锁购买的红宝石）；候选模拟测试 11 项通过。但两种公平预算均未显示胜率收益，固定次数下成本明显增加，因此撤回代码及仅针对此候选的行为测试。`007-demand-candidate.patch` 可在 004 上恢复算法；`007-candidate-tests-full.patch` 是相对初始 Git 基准的完整测试差异，包含此前 004 测试，不应直接叠加到当前测试文件。

同预算复现命令（只有恢复候选 patch 后才是 007 实验）：

```bash
bun scripts/mcts-benchmark.ts --games 12 --time-ms 120 \
  --baseline experiments/mcts/baseline-004.ts --seed 20700000 --max-turns 180
bun scripts/mcts-benchmark.ts --games 12 --playouts 500 \
  --baseline experiments/mcts/baseline-004.ts --seed 20700000 --max-turns 180
```

## 008：被撤回的完整状态 TT

基准 Git 见 `008-base-ref.txt`。唯一算法变量：每次 chooseMove 内建立 Map，完整状态键包含棋盘、有效袋子前缀、牌库/金字塔/预留/皇家卡 id 及顺序、双方全部聚合字段、行动方、额外回合、turnCount、胜负和 RNG。保留 turnCount，不合并不同深度，避免搜索图出现环；不跨回合共享 root 视角回报。相同状态共享节点及其出边，入边统计仍独立；最多缓存 5 万节点。

状态键测试覆盖全部规则字段和袋子尾部；人工构造的不同同色拿取顺序确实产生命中；固定次数可复现。候选完整测试 75 项通过。两种预算下均无和棋、触顶或非法走法。

墙钟实验模拟次数下降约 62%，固定次数实验耗时增加约 19%。尽管确有转置，当前字符串序列化/查表/共享图实现未显示收益，因此撤回全部候选源码、测试和 CLI 扩展，保留 `008-tt-candidate.patch` 及原始日志。该结论不否定增量哈希等更便宜的 TT 实现；也没有单独剖析序列化、GC、图搜索的耗时，不能把总开销全部归因于某一项。

恢复 `008-tt-candidate.patch` 后的复现命令：

```bash
bun scripts/mcts-benchmark.ts --games 12 --time-ms 120 --baseline mcts \
  --tt --seed 20800000 --max-turns 180
bun scripts/mcts-benchmark.ts --games 12 --playouts 500 --baseline mcts \
  --tt --seed 20800000 --max-turns 180
```
