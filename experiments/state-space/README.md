# 可达状态空间估算 (给定初始状态 + seed)

问题: 固定 seed 下从初始局面出发, 有多少个可达状态? 用于评估搜索类算法 (αβ / MCTS) 的理论上限。

工具: `bun scripts/state_space.ts` (参数与口径见脚本头注释; 本目录 `run.log` 为完整输出)。

## 方法

1. **蒙特卡洛采样**: 随机对局测局长分布、强制行动分支、完整走法分支(可选行动 × 条件参数全积)。
2. **分层 BFS + 去重**: 从 `createGame({seed:42, firstSeat:0})` 出发, 按两阶段完整走法
   (可选: 特权子集/补货/顺序 × 强制: 拿/留/买 + 条件参数变体) 展开, 规范化键去重。
   - 键口径: 排除 `rngState/seed/log/turnCount/名字`; bag 按多重集(补货前会重洗);
     牌库按剩余长度(局内只从末尾弹牌, 剩余恒为初始牌库前缀); 全知视角(含双方预留)。
   - 超 10 token 弃置只走引擎默认策略(与仓库全部 bot 一致)。
   - 预算: 每节点 ≤96 边(均匀步进抽样)、每 ply ≤12000 节点(前沿抽样, 计数按保留率放大, 标 `~`)。
3. **解析上界**: 组合计数(BigInt), 忽略可达性, 只作天花板参照。

## 结果 (seed=42, 2024-10 复现见 run.log)

### A/B: 已购卡聚合键 (--abstract)

用户提出的抽象: 已购卡只保留每色(张数/折扣和/分数和), 皇家卡只留总分。
实测与含卡身份的细键**逐 ply 完全一致**(两份日志: run.log vs abstract.log, 累计均 2,445,322, 0 合并)。原因见下节「为什么聚合不减少状态数」。该抽象在跨 seed 商空间/对手建模上仍是对的, 但对固定 seed 可达计数无影响。

### 分支与局长

| 指标 | 值 |
|---|---|
| 强制行动分支(中位/均值/p90) | **10 / ~24 / ~68** |
| 完整走法分支(中位/均值/p90) | **54-64 / ~900-1070 / ~1550** (含特权子集、补货、条件参数) |
| 局长: 随机 vs 随机 | 中位 ~105-107 ply, max ~284 |
| 局长: greedy vs greedy (40 局) | 中位 **70** ply, 范围 61-84 |
| 解析组合上界(全状态空间) | **~9.7×10^96** (棋盘+袋 7.7e20 × 卡牌分配 8.0e59 × 玩家侧 1.6e16) |

完整走法分支的巨大均值来自特权: 手握 2-3 特权时 C(约20格, k) 子集爆炸(单点最大 19 万)。
中位局面没有那么多特权, 搜索实际面对的有效分支更接近 强制分支×少量可选 ≈ 15-30。

### BFS 逐 ply (每 ply 新状态数, ply≥4 为抽样放大估计)

| ply | 展开节点 | 边数 | 新状态 | 去重比(边/新) | 累计(实测入库) |
|---|---|---|---|---|---|
| 1 | 1 | 96 | 96 | 1.00 | 97 |
| 2 | 96 | 9,216 | 9,014 | 1.02 | 9,111 |
| 3 | 9,014 | 862,527 | 810,911 | 1.06 | 820,022 |
| 4 | 12,000 | 1,091,911 | ~73,602,540 | 1.00 | 1,909,205 |
| 5 | 12,000 | 536,250 | ≥536,117 (保留率放大估计 ~3.3×10^9, 预算受限) | 1.00 | 2,445,322 |

- **每 ply 增长率 r ≈ 92.6**(ply 2→3→4: 94 / 90 / 91; ply 5 因边预算受限不采用), 前 5 ply 无任何饱和迹象。
- **去重比 1.00-1.06**: 开局阶段几乎每条边都通向全新状态, 置换(不同走法序列到达同一局面)极少。

### 规模结论

- 可达状态: ply 3 已 81 万, ply 4 ~7×10^7, ply 5 ~3×10^9。按 r≈90 外推,
  ply 7 超过地球沙粒数(~10^19 需 r≈50 再 2 ply), 整局(中位 70-105 ply)必然落在
  **10^40 以上直至解析天花板 ~10^96**(组合上界; 真实可达集受棋谱约束远小于此,
  但对结论无差别)。
- 完整走法树(去重前路径数): ~10^186(随机)/~10^124(greedy) —— 纯参照。

### 对搜索算法的含义

| 节点预算 | 可全宽穷尽的深度 (r≈90) |
|---|---|
| 1e5 | 3 ply |
| 1e6 | 4 ply |
| 1e7 | 4 ply |
| 1e8 | 5 ply |

1. **穷尽不可能**: 全宽搜索 4-5 ply 封顶(与 `ab` 的深度 4 迭代加深实测一致)。
   更深只能靠剪枝(αβ/启发式排序)或采样(MCTS)。
2. **置换表前期收益低**: 前 5 ply 去重比 ~1.0, TT 省不了多少节点;
   mcts2 的跨回合子树复用命中(64-75%)来自"对手走完回到已知局面"的根局部对齐, 不是普适 TT。
3. **真实有效分支 ≈ 15-30**(特权稀疏时的中位局面), 深度优先+好剪枝实际能看 6-8 ply;
   特权多的局面(分支 10^3+)是搜索瓶颈, 值得在候选生成端专门剪(现有 mcts 的 privilegePlans 已做)。
4. **求解/穷举类方法(端局数据库、逆向可达)完全不可行** —— 空间 10^40+ 起步。

### 为什么已购卡聚合不减少状态数 (固定 seed)

1. **守恒**: 牌库只在开局洗一次, 局内只从末尾弹牌; 弹出的牌去向全部记录在状态里。
   已购集合 = 初始牌库后缀 − 金字塔现存 − 双方预留, 是其余字段的**函数**。
   聚合只是删冗余字段, 不提供新合并机会。
2. **顺序置换也几乎不产生合并**: 同槽位不同购买顺序 → 牌库顶牌进不同槽 → 金字塔不同 → 仍不合并。
   真正可合并的只剩「从预留区买入的顺序」与皇家卡领取顺序, ply≤5 内几乎不存在(实测 0)。
3. 指数增长 r≈90 来自棋盘/袋/token/金字塔的发散, 与已购卡记账无关;
   聚合不能(也不可能)压住它。

跨 seed 视角则相反: 解析上界中卡牌分配项 8e59 会塌缩为 P(67,12)×C(55,3)×C(52,3)×每色聚合元组,
数量级显著下降 —— 那是博弈论商空间的正确抽象。

### 复现

```bash
bun scripts/state_space.ts --games 60 --depth 6 --cap-nodes 12000 --max-edges 2500000           # 细键 -> run.log
bun scripts/state_space.ts --games 60 --depth 6 --cap-nodes 12000 --max-edges 2500000 --abstract # 聚合键 -> abstract.log
# ~10 分钟/次 (吞吐 ~4000-5000 applyMove/s, structuredClone 为瓶颈)
```
