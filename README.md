# Splendor Duel Arena · 璀璨宝石对决

Go backend with the existing Chinese browser UI. Local agents: greedy, alpha-beta, and MCTS. No model credentials, LLM dependencies, or streaming transport are required.

## Run

Requires Go 1.25 or later. The server has no external Go dependencies.

```sh
go run ./cmd/server                    # http://localhost:3000
go build -o /tmp/splender-server ./cmd/server
PORT=3001 /tmp/splender-server
```

Run from the repository root, or set `PUBLIC_DIR` and `SESSIONS_DIR`. Sessions default to `sessions/` and remain compatible with the original JSONL seed/move format. Resuming an old LLM or random session selects greedy unless a supported agent is supplied explicitly.

## Test

```sh
go test ./...                         # engine, search, HTTP, recording/replay
go test -race ./...                    # goroutine and shared-state checks
go test ./internal/game -cover        # engine coverage
```

The Go engine is tested against **1,956 reference transitions across 20 games**, generated by the original TypeScript engine. Fixtures cover greedy and random games, purchases, privileges, voluntary/forced replenishment, abilities, and deterministic RNG. The fixtures are frozen historical data and run without the retired TypeScript implementation. Separate rule tests check illegal actions, payment, hidden reservations, royal milestones, extra turns, discard limits, all three victory conditions, input immutability, and card/token conservation.

Bun is optional for the preserved browser adapter, move preview, layout, and HTTP end-to-end tests:

```sh
bun run test:ui                        # adapter and move previews
# In another terminal, against the Go server:
ARENA_URL=http://localhost:3000 bun run test:e2e
```

## Agents and parallel matches

```sh
go run ./cmd/arena -games 10 -jobs 2 -a mcts@1000 -baseline greedy
go run ./cmd/arena -games 10 -jobs 2 -a ab@1000 -baseline greedy
go run ./cmd/arena -games 6 -jobs 1 -a ab/8@1000 -baseline ab@1000
```

`@1000` is a per-move wall-clock budget in milliseconds (default 4000; maximum 120000). `mcts/8@1000` runs eight independent search trees in goroutines and merges root visits. `ab/8@1000` distributes alpha-beta root moves across eight workers; `par-ab` selects up to eight workers. Each depth must complete all root moves before replacing the previous result, and ties follow serial move order. The depth limit remains four. `-jobs` runs multiple matches in goroutines. All bots search the full server state, including actual deck and bag order, shuffle RNG, and both players' blind reservations. Parallel MCTS workers share that starting position and use separate rollout randomness. Alpha-beta uses iterative deepening through depth four; MCTS uses UCT and greedy rollouts. Alpha-beta uses the server’s immutable Go rule engine. MCTS uses a compact simulation kernel with array-based state, encoded moves, and direct heuristic scoring; seeded differential tests check its generated moves and transitions against the authoritative engine. MCTS moves in session JSONL records include `search: {simulations, moveSimulations, winRate}` for later analysis.

MCTS disables voluntary replenishment by default. Enable it with `mcts/8+refill@1000` in the arena or `"includeRefill": true` in the API agent config. The flag applies to both tree search and rollouts; forced replenishment remains available regardless. Enabled replenishment uses the actual bag order and shuffle state, grants the opponent a privilege, and can precede a privilege-assisted purchase. The chosen move records replenishment explicitly, so replay and parallel root statistics preserve that choice.

The browser still offers human play, step/auto agent play, and saved-session resume. Only its transport adapter and the removed agent controls changed. Old `ab`, `mcts2`, and `par-mcts2` specs are compatibility aliases for alpha-beta, MCTS, and parallel MCTS respectively. The Go MCTS ports the TypeScript compact-kernel approach. Default arena and HTTP searches use fresh trees; `search.Session` supports retaining subtrees while checking that the full state and refill policy still match. Historical strength measurements apply to the TypeScript agents. Run `go test ./internal/search -run '^$' -bench 'Benchmark(Rollout|MCTS)$' -benchmem` to measure Go rollout cost and search throughput on the saved single-token position.

## Layout

| Path | Responsibility |
| --- | --- |
| `internal/game/` | Rules, immutable state transitions, official card data, deterministic RNG |
| `internal/search/` | Greedy, alpha-beta, independent MCTS trees and root aggregation |
| `internal/session/` | JSONL recording, deterministic replay, flattened resume prefixes |
| `internal/httpapi/` | Per-game synchronization, bot request coalescing, versioned DTOs, legacy route adapter |
| `cmd/server/` | HTTP startup and graceful shutdown |
| `cmd/arena/` | Concurrent local match comparisons |
| `public/api.js` | Browser transport/schema adapter |
| `public/` | Original UI, card images, move previews |
| `test/` | Browser adapter, move preview, layout, and HTTP end-to-end tests |
| `experiments/` | Historical research results and notes; old TypeScript executables retired |

The public interface is `/api/v1`; existing `/api/new`, `/api/state/{id}`, etc. remain available for compatibility. Changes to future versions should be translated in `public/api.js`, rather than spread through rendering code. See [the API contract](docs/api.md).

Each game has its own mutex. Searches run outside it, so static resources, other games, and state reads remain available. Duplicate bot/step requests share an in-flight operation. Disconnecting one caller does not cancel the shared turn; shutting down the server does. A process-wide semaphore bounds concurrent searches; parallel MCTS trees are separately configured per agent.
