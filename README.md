# Splendor Duel Arena · 璀璨宝石对决

Go backend with the existing Chinese browser UI. Local agents: greedy, alpha-beta, and MCTS. No model credentials, LLM dependencies, or streaming transport are required.

## Run

Requires Go 1.25 or later. The server has no external Go dependencies.

```sh
go run ./cmd/server                    # http://localhost:3000
go build -o /tmp/splender-server ./cmd/server
PORT=3001 /tmp/splender-server
```

Run from the repository root, or set `PUBLIC_DIR` and `SESSIONS_DIR`. Sessions default to `sessions/` and remain compatible with the original JSONL seed/move format. Resuming an old LLM or random session selects greedy unless a supported agent is supplied explicitly.

## Test

```sh
go test ./...                         # engine, search, HTTP, recording/replay
go test -race ./...                    # goroutine and shared-state checks
go test ./internal/game -cover        # engine coverage
```

The Go engine is tested against **1,956 reference transitions across 20 games**, generated by the original TypeScript engine. Fixtures cover greedy and random games, purchases, privileges, voluntary/forced replenishment, abilities, and deterministic RNG. Separate rule tests check illegal actions, payment, hidden reservations, royal milestones, extra turns, discard limits, all three victory conditions, input immutability, and card/token conservation.

Bun is optional for browser adapter tests, original reference tests, and fixture regeneration:

```sh
bun test test/api.test.ts
bun run test:reference
bun run fixtures                       # regenerate committed TypeScript parity traces
# In another terminal, against the Go server:
ARENA_URL=http://localhost:3000 bun run test:e2e
```

## Agents and parallel matches

```sh
go run ./cmd/arena -games 10 -jobs 2 -a mcts@1000 -baseline greedy
go run ./cmd/arena -games 10 -jobs 2 -a ab@1000 -baseline greedy
```

`@1000` is a per-move wall-clock budget in milliseconds (default 4000; maximum 120000). `mcts/8@1000` runs eight independent search trees in goroutines and merges root visits. `-jobs` runs multiple matches in goroutines. Alpha-beta uses iterative deepening through depth four; MCTS uses UCT and greedy rollouts. Both use the same Go rule engine as the server.

The browser still offers human play, step/auto agent play, and saved-session resume. Only its transport adapter and the removed agent controls changed. Old `ab`, `mcts2`, and `par-mcts2` specs are compatibility aliases for alpha-beta, MCTS, and parallel MCTS respectively. The Go MCTS is a new implementation: it does not retain the TypeScript MCTS2 subtree reuse or its specialized simulation kernel; historical strength measurements apply to the TypeScript agents.

## Layout

| Path | Responsibility |
| --- | --- |
| `internal/game/` | Rules, immutable state transitions, official card data, deterministic RNG |
| `internal/search/` | Greedy, alpha-beta, independent MCTS trees and root aggregation |
| `internal/session/` | JSONL recording, deterministic replay, flattened resume prefixes |
| `internal/httpapi/` | Per-game synchronization, bot request coalescing, versioned DTOs, legacy route adapter |
| `cmd/server/` | HTTP startup and graceful shutdown |
| `cmd/arena/` | Concurrent local match comparisons |
| `public/api.js` | Browser transport/schema adapter |
| `public/` | Original UI, card images, move previews |
| `src/`, `experiments/` | TypeScript rule/search references and historical research; not used by the Go server |

The public interface is `/api/v1`; existing `/api/new`, `/api/state/{id}`, etc. remain available for compatibility. Changes to future versions should be translated in `public/api.js`, rather than spread through rendering code. See [the API contract](docs/api.md).

Each game has its own mutex. Searches run outside it, so static resources, other games, and state reads remain available. Duplicate bot/step requests share an in-flight operation. Disconnecting one caller does not cancel the shared turn; shutting down the server does. A process-wide semaphore bounds concurrent searches; parallel MCTS trees are separately configured per agent.
